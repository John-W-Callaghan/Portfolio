Arithmetic Formatter

This project showcases how I implemented a function called `arithmetic_arranger` to organize and display simple arithmetic problems in a user-friendly format. The function accepts a list of problems and returns them arranged neatly, with options to display the answers. Below, I outline the key steps I followed in building this project:

1. Function Definition and Input Validation: I began by defining the function `arithmetic_arranger`, which accepts a list of arithmetic problems and an optional boolean parameter to show answers. The first step is to validate the input to ensure it meets specific criteria. If more than five problems are provided, the function returns an error message stating "Error: Too many problems."

2. Problem Arrangement Initialization: To organize the output, I created a list called `arranged_problems` with four empty strings. This list will later be used to store each part of the formatted problems: the first operand, the second operand with the operator, the line, and the result if requested.

3. Parsing Each Problem: I looped through each problem in the input list, splitting the string into its components: the first operand, the operator, and the second operand. This step allows me to perform validations and computations on each individual problem.

4. Operator Validation: I checked if the operator is either '+' or '-'. If not, the function returns "Error: Operator must be '+' or '-'." This step ensures that only valid arithmetic operations are processed.

5. Digit and Length Validation: I validated that both operands contain only digits and that they do not exceed four digits in length. If any operand fails these checks, the function returns appropriate error messages such as "Error: Numbers must only contain digits." or "Error: Numbers cannot be more than four digits."

6. Performing Calculations: Depending on the operator, I performed the corresponding arithmetic operation (addition or subtraction) and stored the result. This ensures that the final output includes the correct answer when requested.

7. Formatting the Output: I calculated the width required for each problem based on the longest operand, ensuring proper alignment. The arranged output is built by right-justifying the operands and results and left-justifying the operator, providing a clean presentation.

8. Returning the Final Arrangement: Finally, the function returns the arranged problems either with or without the answers, depending on the `show_answers` parameter. If the user requests answers, an additional row for the results is appended to the output. This feature enhances the usability of the function by allowing users to see their computations alongside the formatted problems.

This project provided me with valuable experience in implementing input validation, string manipulation, and formatted output in Python, reinforcing my skills in programming and problem-solving.

Budget App

This project involves the implementation of a `Category` class designed for budgeting and expense tracking, alongside a function called `create_spend_chart` to visualize spending across different categories. Below are the steps I followed to develop these components:

1. Class Definition: I started by defining the `Category` class, which requires a name upon initialization. This class contains a ledger, represented as a list, to track deposits and withdrawals related to the category.

2. Deposit Method: I implemented the `deposit` method, allowing users to add an amount to the ledger with an optional description. The deposit records the transaction as a dictionary containing the amount and description.

3. Withdraw Method: The `withdraw` method enables users to deduct an amount from the category's balance. It first checks if there are sufficient funds using the `check_funds` method. If funds are available, it records the withdrawal as a negative amount in the ledger and returns `True`; otherwise, it returns `False`.

4. Balance Calculation: The `get_balance` method calculates the current balance by summing all amounts in the ledger. This method is essential for providing users with an up-to-date view of their finances.

5. Transfer Method: I introduced a `transfer` method to allow users to move funds from one category to another. This method checks if sufficient funds are available, withdraws the specified amount from the current category, and deposits it into the target category with appropriate descriptions.

6. Funds Check: The `check_funds` method verifies if the requested withdrawal amount does not exceed the current balance. This validation ensures that users cannot withdraw more than they have.

7. String Representation: I defined the `__str__` method to provide a user-friendly string representation of the `Category` object. This method formats the category name, individual transactions, and the total balance, ensuring the output is clearly readable.

8. Spend Chart Function: The `create_spend_chart` function generates a visual representation of spending by category. It calculates the total withdrawals for each category and determines the percentage spent relative to total expenses. The chart is formatted to display percentage labels alongside a graphical representation using 'o' to indicate spending levels.

9. Chart Formatting: The function creates a horizontal bar chart, listing percentages from 100% down to 0%. It also formats the category names vertically alongside the chart, ensuring the chart is clear and informative. This dual-axis presentation enhances the visualization of spending habits.

This project has enhanced my understanding of object-oriented programming principles, particularly in how to structure classes and methods effectively. Additionally, creating the spend chart has improved my skills in data visualization and string formatting in Python.

Polygon Area Calculator

This project involves the implementation of a `Rectangle` class and a `Square` class that inherits from it. These classes provide a structured approach to handling geometric shapes and calculating various properties. Below, I outline the key components and functionalities:

1. Rectangle Class Definition: I began by defining the `Rectangle` class, which requires a width and a height as parameters during initialization. These parameters are stored as attributes to represent the dimensions of the rectangle.

2. Setters for Width and Height: I implemented methods `set_width` and `set_height`, allowing users to modify the width and height of the rectangle after its creation. This provides flexibility in adjusting the dimensions as needed.

3. Area Calculation: The `get_area` method calculates the area of the rectangle by multiplying its width by its height. This method provides a quick way to obtain the rectangle's size.

4. Perimeter Calculation: I defined the `get_perimeter` method, which computes the perimeter of the rectangle using the formula \(2 \times (\text{width} + \text{height})\). This method is essential for understanding the rectangle's boundary length.

5. Diagonal Calculation: The `get_diagonal` method returns the length of the diagonal of the rectangle, calculated using the Pythagorean theorem. This provides insight into the rectangle's dimensions from a geometric perspective.

6. Picture Representation: The `get_picture` method creates a visual representation of the rectangle using asterisks ('*'). If the rectangle's dimensions exceed 50 units, the method returns a message indicating that it is "Too big for picture." Otherwise, it constructs a string representation of the rectangle's shape.

7. Amount Inside: I implemented the `get_amount_inside` method to determine how many instances of a given shape can fit inside the rectangle. This method uses integer division to calculate how many shapes can fit along the width and height.

8. String Representation: The `__str__` method provides a user-friendly string representation of the rectangle, detailing its width and height. This enhances usability by allowing easy identification of the rectangle's dimensions.

9. Square Class Definition: I created the `Square` class as a subclass of `Rectangle`. The square is initialized with a single side length, which sets both width and height to the same value. This encapsulates the properties of a square while leveraging the existing rectangle functionality.

10. Set Side Method: The `set_side` method in the `Square` class allows users to set the length of a side, automatically adjusting both width and height. This ensures that the square maintains its geometric properties.

11. Overridden Setters: I overridden the `set_width` and `set_height` methods in the `Square` class to call the `set_side` method, ensuring that changing either dimension updates both sides to remain consistent with the properties of a square.

12. String Representation of Square: The `__str__` method for the `Square` class provides a string representation that reflects its side length, making it easy to understand its dimensions.

This project has enhanced my understanding of object-oriented programming concepts such as inheritance, method overriding, and encapsulation while providing practical examples of how to manage geometric shapes programmatically.

Probability Calculator

This project involves creating a simulation of drawing balls from a hat using a `Hat` class and an `experiment` function to calculate the probability of drawing specific colored balls. Below, I outline the key components and functionalities:

1. Hat Class Definition: The `Hat` class is designed to represent a collection of colored balls. During initialization, it accepts keyword arguments that specify the colors of the balls and their respective counts. This allows for the dynamic creation of a hat filled with different colored balls based on user input.

2. Contents Initialization: In the constructor (`__init__`), I initialize the `contents` attribute as an empty list and populate it by iterating over the keyword arguments. Each color is added to the `contents` list according to its specified count, creating a representation of the balls in the hat.

3. Ball Drawing Functionality: The `draw` method is responsible for simulating the drawing of balls from the hat. It takes an integer parameter, `num_balls`, which specifies how many balls to draw. If the number of balls requested is greater than or equal to the number of balls in the hat, the method returns all the contents of the hat.

4. Random Ball Selection: If fewer balls are requested, the method proceeds to randomly select balls from the `contents`. Using `random.choice`, it selects a ball, removes it from the `contents`, and appends it to the `drawn_balls` list. This ensures that each ball can only be drawn once per experiment.

5. Experiment Function: The `experiment` function simulates multiple experiments to determine the probability of drawing a specific combination of balls. It accepts four parameters: `hat` (the instance of the `Hat` class), `expected_balls` (a dictionary specifying the expected counts of each color), `num_balls_drawn` (the number of balls to draw in each experiment), and `num_experiments` (the total number of experiments to conduct).

6. Successful Experiment Counting: Within the `experiment` function, I maintain a count of successful experiments where the drawn balls match the expected counts. For each experiment, a deep copy of the hat is created using `copy.deepcopy` to ensure that each experiment starts with the original set of balls.

7. Drawing Balls in Experiments: After drawing the specified number of balls, I create a dictionary (`drawn_dict`) that counts the occurrences of each color in the drawn balls. This allows for easy comparison with the `expected_balls` criteria.

8. Success Check: A success check is performed to ensure that all expected colors and their counts are met in the drawn balls. If any expected color is not found or its count is less than required, the experiment is marked as unsuccessful.

9. Probability Calculation: At the end of all experiments, the function calculates the probability of successfully drawing the expected combination of balls by dividing the number of successful experiments by the total number of experiments conducted.

This project has reinforced my understanding of object-oriented programming and probability simulations, demonstrating how to model real-world scenarios using classes and functions in Python.

Time Calculator

This project features a function called `add_time` that allows users to add a specific duration to a given start time while considering AM/PM transitions and optional weekday tracking. Below, I detail the steps I followed in implementing this function:

1. Function Definition and Input Parsing: I started by defining the `add_time` function, which takes three parameters: the `start` time in "HH:MM AM/PM" format, the `add` duration in "HH:MM" format, and an optional `day` parameter representing the starting day of the week. The first step is to split the `start` time into its components (time and period) and convert the hour and minutes to integers for further calculations.

2. Duration Conversion: I parsed the `add` parameter, converting the hours and minutes from the duration string into integers using the `map` function. This enables straightforward arithmetic operations on the time values.

3. Carrying Minutes and Hours: I calculated the total minutes by adding the minutes from the `start` time and the `add` duration. To handle cases where the total minutes exceed 60, I used the `divmod` function to determine how many hours to carry over and the remaining minutes. Subsequently, I added the carry to the hour value.

4. Handling AM/PM Transitions: I calculated how many 12-hour cycles the total hours have gone through using `divmod`, which helps in determining the current AM/PM period. The period is updated based on the number of cycles that have occurred. If the hour value becomes zero after calculations, I reset it to 12 for proper formatting.

5. Formatting Minutes: To maintain the standard time format, I ensured that minutes are always displayed as two digits. If the calculated minutes are less than 10, I prepend a zero to the minute value.

6. Weekday Calculation: If the optional `day` parameter is provided, I initialized a list of days of the week and computed the new day based on how many periods (days later) have passed. The new day is formatted and included in the final output.

7. Result Formatting: I constructed the final output string, which includes the updated hour, minutes, period (AM/PM), any new day information, and a note about how many days later the time falls if applicable. This enhances user understanding of the time adjustment.

8. Return Statement: The function returns the formatted time string, providing a clear and concise representation of the new time after the specified duration has been added, along with any additional information about the day or the next day.

This project has reinforced my skills in working with time manipulations, string formatting, and handling user input in Python, ultimately improving my understanding of these concepts.
